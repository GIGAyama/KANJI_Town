# 運用・障害対応

## 利用者が問題を報告するとき

1. 設定の「アプリの状態とサポート」を開きます。
2. 「状態を再確認」を押します。
3. 問題が続く場合だけ「診断ファイルを保存」を押し、保存されたJSONをサポート担当へ渡します。

診断ファイルには、アプリと配信のバージョン、端末保存・通信・Service Worker・クラウド同期の状態、直近20件の技術的なエラーだけが含まれます。漢字の学習内容、氏名、メールアドレス、パスワード、認証トークンは含めません。エラー文に含まれたメールアドレス、UUID、認証情報は保存前に伏せ字へ変換します。

## デプロイの確認

`main` へのpushでは、品質チェック、GitHub Pagesへのデプロイ、配信確認の順に実行します。

- `npm test`
- 本番依存関係の脆弱性監査
- 本番ビルドとバンドル容量チェック
- GitHub Pagesへのデプロイ
- アプリシェルと `release.json` の取得
- 配信中のcommit SHAとデプロイ対象SHAの一致確認

配信確認はGitHub Pagesの反映時間を考慮して最大約60秒再試行します。成功しない場合は古いリリースが配信されている可能性があるため、Actionsの `verify-deployment` を確認します。

## 診断情報の保持

- 診断履歴は利用者の端末内にだけ保存します。
- 最大20件を超えた古い履歴は自動で削除します。
- 設定画面の「履歴を消す」からいつでも削除できます。
- 外部の解析サービスへ自動送信しません。
