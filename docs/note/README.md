## note に貼る手順

1. note の新規記事で、1行目の見出しをタイトル欄に貼ります。
   `# 教室で使えるかもしれないもの作り #◯ 「一度合格したら、それで終わり」にしない。忘れたころに戻ってくる漢字学習アプリ「マイ漢字タウン」`
2. 2行目以降の本文を、そのまま本文欄に貼ります。
   見出し以外の Markdown は使っていないので、貼り直しの手間はありません。
3. 画像は自動で入らないので、`images/` の中のファイルを手で上げます。
   本文の `![...](images/xx-....png)` の行が、その画像を置く位置です。
   貼り終えたら `![...]` の行は消してください。
4. 画像のすぐ下にある一文は、note のキャプション欄へ移してください。
5. ハッシュタグは本文のいちばん最後にある行をそのまま使えます。
   前の版にはこの節がまるごと無かったので、今回入れました。

## 取材メモ

書き手から聞いた話です。記事の 🏫 はじめに と 🔁 と 📖 は、ここから書いています。

- 勤めている自治体では、教科の学習に使うデジタルドリルを自治体として導入している。
  漢字のドリルもその中に入っていて、子どもたちはいつでも取り組める
- そのドリルは、自治体が認めるものだけあって、字形も、始筆も、終筆も、
  とめやはねも、筆順まで採点してくれる。機能としては十分
- ただ、採点が厳しすぎて学習に前向きになれない
- 一度学習した文字をあらためて学習し直す仕組みが、アプリの側に用意されていない。
  合格したら、それで終わり
- はじめのうちは一生懸命やる。けれど学期が進み、学年が上がるにつれて
  子どもが使わなくなっていくのを何度も見てきた
- そこで、一度学習したら終わりではなく、忘れるころに何度でも復習できる仕組みを
  アプリの側に持たせようと思った
- ただ漢字の学習をするだけだとつまらないので、学習を進めることで
  より楽しい遊びができるようになるアプリを目指した
- アプリとしての面白さだけにならないよう、漢字が身につくことにもこだわった
- 学習は4つに分けた。まず読めること、お手本を見ること、なぞり書き、
  自分の力で書くこと。この4つをしっかり取り組んで習得を目指す
- 一度練習しただけで身についたとはならない。何度も繰り返し復習していく中で
  身につけていくイメージ
- 学校では、教材会社が出している漢字ドリルや漢字ドリルノートを一緒に使い、
  教科書に出てくる順で漢字の学習を進めていくことが多い。
  そのドリルを中心とした学習の、良き伴走者になれるところを目指した
- 先生も子どもも、それぞれ自分で漢字を複数選んで、学習したい漢字のまとまりを作れる。
  作ったまとまりはクラスルームなどを通じてみんなに配ることもできる
- 作ったドリルで、漢字テストに向けた練習をしたり、覚えていない漢字を確かめるために
  テストをしたり、いまの自分に足りないところを補うかのように、
  どういう学習の方法でどの漢字を学習するかを、考えて進めることができる

「良き伴走者」は、書き手の言葉をそのまま本文に残してあります
（📖 の「紙のドリルと一緒に使う」）。

## 撮影中に見つかった不具合（このブランチで先に直してあります）

ドリルを「リンクで配る」画面のQRコードは、qrcode というライブラリを CDN から
読み込んで描いています。その取得先が `qrcode@1.5.4` の `build/qrcode.min.js` を
指していましたが、qrcode は 1.5.0 で `build/` を公開物から外しているため、
このファイルは CDN に存在しません。

画面が壊れて見えないので気づけません。1本目が404になると、予備に置いてある
unpkg の 1.4.4 が読み込まれて QR は出るからです。困るのは校内フィルタリングで、
記事や資料で「cdn.jsdelivr.net を許可してください」と伝えている学校では、
実際に効いているのは unpkg.com のほうになり、QRコードだけが出なくなります。

1本目を、`build/` を同梱している 1.4.4 に合わせました。予備は変えていません。

```

```

## 撮り直すとき

今回は `21-drill-share-link.png` の1枚だけを撮り直しました。
前の版のこの画像には、URL欄とQRコードに旧アドレス `gigayama.github.io` が
写ったままで、本文と食いちがっていたためです。

`report.json` はこの1枚ぶん更新されていません。次に全体を撮り直すときは、
`capture.mjs` の撮り比べで21番が「変わった」と出ないことがあります。

手順の要点です。

1. `npm ci` のあと `npm i --no-save playwright qrcode` でまとめて入れます。
   `--no-save` で別々に入れると、あとから入れたものが前のものを消します
2. `/etc/hosts` に `127.0.0.1 kanji-town.giga-school.com` を足します。
   画面に出る共有URLとQRコードを、本番と同じ見た目にするためです
3. `npm run build` してから、自己署名の証明書で `dist` を443番から配ります。
   共有URLは `window.location.origin` から作られるので、
   ホスト名だけでなく https であることも本番と合わせる必要があります
4. `capture.mjs` には証明書を無視する口が無いので、この1枚については
   `ignoreHTTPSErrors` を渡せる撮影スクリプトを `.tmp-shots/` に置いて撮りました。
   ビューポートは 390×1500、拡大率は2倍で、前の画像と同じ 780×3000 になります
5. 校内フィルタリングの下と同じで cdn.jsdelivr.net へ出られない環境だったため、
   qrcode と Google Fonts は Playwright の `route()` で手もとのファイルを返しました。
   アプリ側の接続先は書きかえていないので、撮影のための変更はリポジトリに残りません
6. 撮り終えたら `.tmp-shots/` を消し、`/etc/hosts` を戻し、
   `git status` と `git diff` で差分に残っていないことを確かめます

撮影の中身は、花空草青林森の6字で「金よう日の 小テスト」というドリルを作り、
マイドリルの一覧から「リンク」を押すところまでです。
