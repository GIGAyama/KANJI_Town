# note 記事の入稿メモ（マイ漢字タウン・更新版）

連載「教室で使えるかもしれないもの作り」に載せる紹介記事一式です。
前回（#10、2026年3月23日公開）で紹介したあとの大きな更新を、あらためて書き起こしたものです。

```
docs/note/
├── kanji-town-note-article.md   記事本文。そのまま note に貼れる形
├── images/                      実際に操作して撮った画面（27点）
└── README.md                    このファイル
```

## 貼るまえに直すところ

1. **連載番号**。本文1行目の `#◯` を実際の番号に置きかえてください。
   前回のマイ漢字タウンの回が #10 なので #11 以降になるはずですが、
   あいだに別のアプリの回が入っているかどうかが分からなかったので、
   推測で埋めずに `#◯` のまま残してあります。
2. 公開前に、ひとつ前のコミット（結果画面の NaN 修正）を反映してください。
   詳しくは下の「撮影中に見つかった不具合」を読んでください。

## note に貼る手順

1. note の新規記事で、1行目の見出しをタイトル欄に貼ります。
   `# 教室で使えるかもしれないもの作り #◯ 「なぞれた」で終わらせない。書き順まで見てくれる漢字学習アプリ「マイ漢字タウン」`
2. 2行目以降の本文を、そのまま本文欄に貼ります。
   見出し以外の Markdown は使っていないので、貼り直しの手間はありません。
3. 画像は自動で入らないので、`images/` の中のファイルを手で上げます。
   本文の `![...](images/xx-....png)` の行が、その画像を置く位置です。
   貼り終えたら `![...]` の行は消してください。
4. 画像のすぐ下にある一文は、note のキャプション欄へ移してください。
5. ハッシュタグは前回と同じ並びで問題ないと思います。
   #GIGAスクール #ICT教育 #小学校 #漢字 #教育アプリ

## 撮影中に見つかった不具合（公開前に反映してください）

学習の結果画面で、ストーリーステージが「荒野の旅人」から一切進まず、
「次のステージまで 漢字NaN文字 人口NaN人」と表示される状態でした。

`src/data/story-stages.js` のステージ定義はレベル（`minLevel`）だけを持って
いるのに、`ResultView` が存在しない `minKanji` と `minPop` を見ていたためです。

記事とは別のコミットに分けてあります。

```
ed8012f 学習の結果画面でステージが進まず「NaN」と出る不具合を直す
```

## 品質ゲートについて

`npm run check` の画像サイズの上限（150KB）に、記事のスクリーンショットが
引っかかりました。この上限は配信される成果物を軽く保つためのもので、
`docs/` の画像はビルドに含まれず端末へ届きません。そこで
`quality.config.json` に `imageBudgetExemptPrefixes` を足し、
`docs/` 以下だけ上限を見ないようにしています。
アプリ本体の画像はこれまでどおり上限で守られます。

## 撮り直したいとき

撮影は、本番と同じ `https://gigayama.github.io/KANJI_Town/` というアドレスの
まま手もとで配って行いました。画面に出るURLとQRコードを本番と同じ見た目に
するためです。手順の要点は次のとおりです。

1. `npm i --no-save playwright peer peerjs qrcode` でまとめて入れます。
   `--no-save` で別々に入れると、あとから入れたものが前のものを消します。
2. `npm run build` してから、`dist` を `gigayama.github.io` という名前で
   配ります（`/etc/hosts` に `127.0.0.1 gigayama.github.io` を足し、
   自己署名の証明書で443番に立てる）。
3. Chromium は `--ignore-certificate-errors` で起動し、マイクは
   `--use-fake-device-for-media-stream` を渡して音読チャレンジを通します。
4. 書き順の手本（KanjiVG）とQRコードの生成は、ふだんは cdn.jsdelivr.net から
   取り込みます。撮影した環境ではこのアドレスに出られなかったため、
   同じデータを手もとに置いて一時的にそちらを向けました。
   **この差しかえは撮影後に戻してあります。**
   `git status` と `git diff` で差分に残っていないことを確認済みです。

撮影用のスクリプトは `.tmp-shots/` に置いて作業し、納品前に削除しました。
