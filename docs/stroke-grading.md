# 書字の正誤判定ロジック

児童が「正しい書き順・字形・とめはね・点画の交差」を確実に身につけられるようにするための、
書字採点の設計をまとめる。実装は以下の4ファイル。

| ファイル | 役割 |
| --- | --- |
| `src/systems/analyzer.js` | 幾何処理（終筆解析・交差の深さ・リサンプリング・字形比較） |
| `src/systems/strokeKind.js` | KanjiVG の筆画種 → とめ・はね・はらいの正解 |
| `src/systems/strokeGrader.js` | 採点方針（配点・対応づけ・講評） |
| `src/constants/strokeConfig.js` | 判定の閾値（画数に応じた適応を含む） |

採点は `gradeStrokes(userStrokes, strokeData, canvasSize)` に集約され、
テスト・ドリル・ボスバトル・サバイバルのすべてが同じ判定を共有する。

## 配点（合計100点）

| 項目 | 配点 | 見ているもの |
| --- | ---: | --- |
| 字形 | 30 | 経路全体が手本に沿っているか |
| 書き順 | 25 | どの画をどの順で書いたか |
| とめ・はね・はらい | 15 | 終筆の処理 |
| 点画の交差 | 10 | 突き抜けるべき／接するだけの区別 |
| 始点 | 10 | 書き出しの位置 |
| 終点 | 10 | 書き終わりの位置 |

評価できない項目（例：手本に筆画種の情報がなく終筆を判定できない）は、
その配点を残りの項目へ按分する。正しく書けていれば常に100点満点になる。

### 合否の扱い

- **画数が違う** → 0点。別の字になってしまうため部分点を出さない。
- **点画の交差が違う** → `crossMatch: false`。交差の配点は失うが、
  正しく書けた部分の点は残す（全否定して学習意欲を折らないため）。
- **書き順が違う** → 合格ライン未満（`GRADING.ORDER_FAIL_CAP` = 69点）に抑える。
  「三」を下から書いても見た目は同じで字形は満点になるので、
  上限を設けないと書き順の誤りが点数に表れない。

## 設計上の要点

### 1. 「何を書いたか」と「どの順で書いたか」を分ける

まずユーザーの各画を正解の各画へ**最適に対応づける**（ハンガリー法で割り当て問題を解く）。
字形・始点・終点・終筆はその対応づけ先と比べ、書き順は対応づけの並び順で評価する。

- 「形はきれいだが書き順が違う」を切り分けて指導できる。
- 貪欲マッチングだと「三」「川」のように似た画が並ぶ字で対応を取り違え、
  正しく書いていても書き順が誤判定される。全体最適が必要。
- 逆に、どちらを先に書いたか幾何的に区別できない画（対応づけの費用差が
  `ORDER_AMBIGUITY_MARGIN` 未満）は、誤りと断定せず正しい扱いにする。

### 2. 交差は「本数」ではなく「突き抜けの深さ」で測る

交差点から両ストロークの端までの距離のうち最小のものを突き抜け量とする。

- 「土」のようにT字に接するだけ → 端までの距離が0に近い → 交差なし
- 「牛」のように突き抜ける → どちら側にも長さが残る → 交差あり

交差したセグメント対の**本数**で測ると、ゆっくり書けば点が増えて交差と判定され、
速く書けば交差と判定されない、という書く速さ依存の誤判定が起きる。深さは密度に依存しない。

判定は `CROSS_DEPTH_NONE`（0.015）〜`CROSS_DEPTH_CLEAR`（0.045）の間でなだらかに変化させ、
わずかにはみ出しただけでいきなり不正解にはしない。

### 3. とめ・はね・はらいは KanjiVG の筆画種から正解を引く

KanjiVG の各 `<path>` は `kvg:type` に CJK Strokes ブロックの文字で筆画の種類を持つ
（横「㇐」、竖钩「㇚」、撇「㇒」など）。筆画の種類が決まれば終筆の処理も決まる。
対応表は `src/systems/strokeKind.js`。

配点を控えめ（15点）にし、不一致でも部分点（とめ↔はねは0.5）を残しているのは、
文部科学省「常用漢字表の字体・字形に関する指針」が終筆の細部に幅を認めているため。
なぞり書き中も助言は出すが、書き直しは求めない。

**正解が分からないときは褒めない。** 以前は児童の書いた終筆をそのまま
「きれいなハネ！」と肯定していたため、とめるべきところではねても褒めてしまい、
誤りを強化していた。現在は正解不明時は中立の文言のみを返す。

### 4. 許容距離は画数に合わせて縮める

固定閾値（始点0.20）のままだと、20画の字では隣の画の始点まで正解圏に入ってしまい、
判定が事実上機能しない。6画までは従来の緩さを保ち、それ以上は 1/√画数 で縮める
（`getStrokeTolerances`）。なぞり書きの書き出しゲートは、低学年が詰まらないよう
これより少し甘い値を使う（`getGuideTolerances`）。

### 5. 字全体の位置ずれは一定量まで補正する

字がまるごと少し右にずれただけで全画が減点されるのを防ぐため、
外接枠の中心のずれを `GLOBAL_SHIFT_MAX`（0.06）まで打ち消してから比較する。
それを超えるずれは減点として残る。

## 採点結果の返し方（結果画面での説明）

`gradeStrokes` は合計点のほかに、児童へ理由を示すための材料も返す。

| フィールド | 内容 |
| --- | --- |
| `breakdown` | 項目ごとの `{ key, points, max, evaluated }`。按分後の満点込みなので、画面側で配点を再計算しなくてよい |
| `strokeFeedback` | 画ごとの `{ matched, inOrder, shape, reversed, ending }` |
| `details` | 児童向けの講評文 |
| `strokeCountMatch` / `orderMatch` / `crossMatch` | 合否を分ける3条件 |

`evaluated: false` の項目（例：手本に筆画種が無く終筆を採点できない）は `max` も0にしてあり、
「0点を取った」のか「採点対象外だった」のかを画面で区別できる。
画数が違うときは採点そのものを行わないので `breakdown` は空配列になる。

マイドリルのテスト結果画面（`DrillTestView`）は、この内訳と `strokeFeedback` を使って
「どの画で」「どの観点で」点を落としたかを、書いた線の色分けと番号で示している。

## KanjiVG キャッシュの形式

`kvg:type` を持たせるため、IndexedDB のキャッシュは `string[]`（d属性のみ）から
`{d, type}[]` に変わった。旧形式も読めるようにしてあり、オンラインなら取り直し、
取り直せなければ旧データのまま使って終筆の採点だけを見送る。

## テスト

`test/analyzer.test.js` / `test/stroke-grader.test.js`（`npm test`）。
交差判定が書く速さに左右されないこと、書き順の誤りが合格しないこと、
正解不明時に誤って褒めないことなど、教育上重要な性質を回帰テストとして固定している。
