# 書字の正誤判定ロジック

児童が「正しい書き順・字形・とめはね・点画の交差」を確実に身につけられるようにするための、
書字採点の設計をまとめる。実装は以下の4ファイル。

| ファイル | 役割 |
| --- | --- |
| `src/systems/analyzer.js` | 幾何処理（終筆解析・交差の深さ・リサンプリング・字形比較） |
| `src/systems/strokeKind.js` | KanjiVG の筆画種 → とめ・はね・はらいの正解 |
| `src/systems/strokeGrader.js` | 採点方針（配点・対応づけ・講評） |
| `src/constants/strokeConfig.js` | 判定の閾値（画数に応じた適応を含む） |

採点は `gradeStrokes(userStrokes, strokeData, canvasSize)` に集約され、
テスト・ドリル・ボスバトル・サバイバルのすべてが同じ判定を共有する。
毎日の学習のテストは、その結果を `judgeWriting` で「できた／もう1回／てきとう書き」に分ける
（下の「毎日の学習のテストの判定」）。

## 配点（合計100点）

| 項目 | 配点 | 見ているもの |
| --- | ---: | --- |
| 字形 | 30 | 経路全体が手本に沿っているか |
| 書き順 | 25 | どの画をどの順で書いたか |
| とめ・はね・はらい | 15 | 終筆の処理 |
| 点画の交差 | 10 | 突き抜けるべき／接するだけの区別 |
| 始点 | 10 | 書き出しの位置 |
| 終点 | 10 | 書き終わりの位置 |

評価できない項目（例：手本に筆画種の情報がなく終筆を判定できない）は、
その配点を残りの項目へ按分する。正しく書けていれば常に100点満点になる。

### 合否の扱い

- **画数が違う** → 0点。別の字になってしまうため部分点を出さない。
- **点画の交差が違う** → `crossMatch: false`。交差の配点は失うが、
  正しく書けた部分の点は残す（全否定して学習意欲を折らないため）。
- **書き順が違う** → 合格ライン未満（`GRADING.ORDER_FAIL_CAP` = 69点）に抑える。
  「三」を下から書いても見た目は同じで字形は満点になるので、
  上限を設けないと書き順の誤りが点数に表れない。

## 設計上の要点

### 1. 「何を書いたか」と「どの順で書いたか」を分ける

まずユーザーの各画を正解の各画へ**最適に対応づける**（ハンガリー法で割り当て問題を解く）。
字形・始点・終点・終筆はその対応づけ先と比べ、書き順は対応づけの並び順で評価する。

- 「形はきれいだが書き順が違う」を切り分けて指導できる。
- 貪欲マッチングだと「三」「川」のように似た画が並ぶ字で対応を取り違え、
  正しく書いていても書き順が誤判定される。全体最適が必要。
- 逆に、どちらを先に書いたか幾何的に区別できない画（対応づけの費用差が
  `ORDER_AMBIGUITY_MARGIN` 未満）は、誤りと断定せず正しい扱いにする。

### 2. 交差は「本数」ではなく「突き抜けの深さ」で測る

交差点から両ストロークの端までの距離のうち最小のものを突き抜け量とする。

- 「土」のようにT字に接するだけ → 端までの距離が0に近い → 交差なし
- 「牛」のように突き抜ける → どちら側にも長さが残る → 交差あり

交差したセグメント対の**本数**で測ると、ゆっくり書けば点が増えて交差と判定され、
速く書けば交差と判定されない、という書く速さ依存の誤判定が起きる。深さは密度に依存しない。

判定は `CROSS_DEPTH_NONE`（0.015）〜`CROSS_DEPTH_CLEAR`（0.045）の間でなだらかに変化させ、
わずかにはみ出しただけでいきなり不正解にはしない。

### 3. とめ・はね・はらいは KanjiVG の筆画種から正解を引く

KanjiVG の各 `<path>` は `kvg:type` に CJK Strokes ブロックの文字で筆画の種類を持つ
（横「㇐」、竖钩「㇚」、撇「㇒」など）。筆画の種類が決まれば終筆の処理も決まる。
対応表は `src/systems/strokeKind.js`。

配点を控えめ（15点）にし、不一致でも部分点（とめ↔はねは0.5）を残しているのは、
文部科学省「常用漢字表の字体・字形に関する指針」が終筆の細部に幅を認めているため。
なぞり書き中も助言は出すが、書き直しは求めない。

**正解が分からないときは褒めない。** 以前は児童の書いた終筆をそのまま
「きれいなハネ！」と肯定していたため、とめるべきところではねても褒めてしまい、
誤りを強化していた。現在は正解不明時は中立の文言のみを返す。

### 4. 許容距離は画数に合わせて縮める

固定閾値（始点0.20）のままだと、20画の字では隣の画の始点まで正解圏に入ってしまい、
判定が事実上機能しない。6画までは従来の緩さを保ち、それ以上は 1/√画数 で縮める
（`getStrokeTolerances`）。なぞり書きの書き出しゲートは、低学年が詰まらないよう
これより少し甘い値を使う（`getGuideTolerances`）。

### 5. 字全体の位置ずれは一定量まで補正する

字がまるごと少し右にずれただけで全画が減点されるのを防ぐため、
外接枠の中心のずれを `GLOBAL_SHIFT_MAX`（0.06）まで打ち消してから比較する。
それを超えるずれは減点として残る。

## 毎日の学習のテストの判定（`judgeWriting`）

毎日の学習の最後の「テスト」は、採点（`gradeStrokes`）の結果から、書いた字を
**できた／もう1回／てきとう書き**に分けて進める。児童が評価を選ぶボタンは無い。

### なぜ自己採点をやめたか

以前は採点の「おすすめ」を出したうえで4つのボタンから児童が選び、選べるのはおすすめの1段上までだった。
ところが、おすすめが「忘れた」（画数ちがいなど）でも「むずかしい」は選べ、「むずかしい」は合格あつかいだった。
**線を1本引いて「むずかしい」を押すだけで**、新出字なら EXP 50 が入り、その字は「習った字」になり、
1日の目標・連続日数・ミッション・レアドロップまで進んだ。

### 点数だけでは決められない

「おすすめが『忘れた』なら必ずやり直し」にすれば抜け道は閉じるが、それでは**ていねいに書いた子が進めなくなる**。
`gradeStrokes` は線の交わり（つきぬける／つきぬけない）に厳しく、接するだけの画が箱の3%（300px のマスで 9px）
はみ出すと「交わりがちがう」になる。ゆびで書く低学年の字をまねた試算（下の表）では、
画数も書き順も正しい字の **35%（ふつうの子）〜78%（とても雑な子）** がおすすめ「忘れた」になった。
これまでは児童が「むずかしい」を選ぶことで、この厳しさを逃がしていたことになる。

そこで「字として読み取れるか」を点数とは別に測り（`measureAttempt`）、読み取れる字は通して、
読み取れない字だけをやり直しにした。

### 決まり

| 判定 | 条件 | 評価 |
| --- | --- | --- |
| できた | 画数が合っていて 40 点以上 | 80 点以上 easy・55 点以上 good・ほかは hard |
| できた（きずあり） | 画数が合っていて、線の交わりか書き順がちがい、50 点以上 | hard まで |
| もう1回 | 上のどちらでもなく、てきとう書きでもない | again |
| → 2回目から通す | もう1回のうち「読み取れる字」で、この学習で同じ字を1回以上やり直している | hard |
| てきとう書き | 読み取れない字で、下のどれかに当てはまる | again＋ペナルティ |

- **読み取れる字**：字全体の大きさと位置をお手本にそろえたうえで（上限なし）、お手本の画の 60% 以上が
  書いた線のどれかと形・位置が合い、画数の差がお手本の 30% 以内（1画の差はいつも認める）。
  1画多い（ゆびがはなれて切れた）・1画たりない・小さく書いた、がここに入る。
  1回目は理由（「1かく おおいよ」「字が小さいよ」）を伝えてやり直してもらい、2回目からは hard で通す
  （端末やゆびのくせで画が切れるような、子どもには直せない理由で同じ字に止まらないように）。
- **てきとう書き**：お手本の画数の 1/3 以下しか書いていない（3画以上の字）／お手本の画数の2倍＋5画以上書いた／
  書いた線の長さの合計がお手本の 10% に満たない。**形は見ない**（形だけで決めると、ほかの字とまちがえて
  書いた子まで巻きこむ）。
- 合格の下限を 30 点（以前のおすすめ「むずかしい」の下限）から 40 点に上げ、きずのある字は 50 点にしたのは、
  同じ画数のほかの字（「土」に「工」）を通しにくくするため。3画の字はどれも「線が3本」なので、
  30 点のままだと同じ画数のほかの字の 6.6% が通った（40／50 点で 1.0%）。
- 値は `src/constants/strokeConfig.js` の `JUDGE`。

### 試算（2026-11-16）

1〜2年の全240字と3〜6年から抜いた131字（計371字）に、書き方ごとに4回ずつ（各 約1,480 回）通した結果。
「雑さ」は、画の始点と終点をそれぞれ箱の何%までずらすか（ふつう4%・雑7%・とても雑10%）と、字全体の位置・大きさのずれ。
**実際の児童の筆跡ではなく、作った線での試算**である点に注意（実物の筆跡を集めて確かめてはいない）。

| 書き方 | 以前のおすすめが「忘れた」 | できた | もう1回 | てきとう書き | 2回目に通る |
| --- | ---: | ---: | ---: | ---: | ---: |
| ていねい | 2.6% | 100% | 0% | 0% | — |
| ふつう | 35.1% | 100% | 0% | 0% | — |
| 雑 | 63.4% | 99.5% | 0.5% | 0% | 99.9% |
| とても雑 | 78.2% | 82.2% | 17.8% | 0% | 95.8% |
| 小さい（お手本の3〜4.5割） | 61.3% | 27.0% | 73.0% | 0% | 100% |
| 1画多い（ゆびがはなれた） | 100% | 0.1% | 99.9% | 0% | 97.4% |
| 1画たりない | 100% | 0% | 100% | 0% | 93.1% |
| 書き順ちがい | 33.4% | 99.8% | 0.2% | 0% | 100% |
| 半分まで書いた | 100% | 0% | 100% | 0% | 9.9% |
| 線1本 | 99.9% | 0.1% | 2.9% | 97.0% | 0.2% |
| 点1つ | 100% | 0% | 0% | 100% | 0% |
| ぐるぐる1本 | 100% | 0% | 3.0% | 97.0% | 0% |
| 画数ぶんのでたらめな線 | 99.9% | 0% | 100% | 0% | 0.5% |
| 画数ぶんの点 | 100% | 0% | 0% | 100% | 0% |
| 同じ画数のほかの字 | 96.9% | 0%（全組では 1.0%） | 100% | 0% | 2.1% |

- 「線1本」が 3% だけ「もう1回」になるのは、1〜2画の字（一・二・十・人 など）。半分は書いているので、
  てきとう書きにはしない（通りもしない）。
- 「とても雑」の 17.8% は1回やり直しになるが、ほとんどが2回目に通る。てきとう書きには1件もならない。
- 「1画だけ書いてやめた」「画数の1/3まで」は、てきとう書きになる（3画以上の字）。思い出せないときのために
  「わからない」ボタン（答えを見てやり直す。ペナルティなし）を置き、てきとう書きの1回目は注意だけにしてある。
- ボス・サバイバル・マイドリルのテストは `gradeStrokes` の点数だけで合否を決めていて、この判定は使っていない。
  上の表の「以前のおすすめが『忘れた』」の割合は、それらのモードでていねいに書いた字が不正解になる割合の
  目安でもある（線の交わりのしきい値 `CROSS_DEPTH_*` を見直す材料になる）。

### てきとう書きのあつかい

- 判定が出た時点で、その日の記録（`stats.daily[日付].careless`）と、その回の学習（`sessionData.carelessCount`）に数える。
  ボタンを押す前にやめても残る。再読みこみでも消えない（チェックポイントに入れる）。
- 1回の学習で1回目は注意だけ。2回目からは1回ごとに、その回の学習でもらえる EXP（と、そこから換算するコイン）を
  10% 減らす。上限は 50%（`src/constants/gameConfig.js` の `CARELESS`、計算は `src/systems/careless.js`）。
- その字は「忘れた」と同じあつかい（間隔反復は学習中に戻り、技能点は下がる）。
- 学習きろくに「きょう／7日間」の回数を出す。0回のあいだは出さない。

### やり直しと、次の学習へ回すこと

- もう1回になった字は、今までの「忘れた」と同じく出題の最後に回り、お手本（書き順・なぞり）から出なおす。
- 同じ字を3回やり直してもできないときは、その字をこの学習から外す（`SESSION.MAX_RETRIES`）。
  記録は「忘れた」のままなので、次の学習でまた出る。宿題の練習は、外した字があるあいだは「できた」にしない。
- 答え合わせのあとは、ボタンを押すまでタブを切りかえられない。切りかえられると、答えを見てからテストに戻って
  書きなおせ、やり直しもてきとう書きも記録に残らなかった。
- 1字もできていない学習は、学習の回数・「セッション」のミッション・レアドロップに数えず、連続日数も付けない。
- はじめての字は、1回目でできなくても、できたときに新出字として数える（EXP 50 と「新しい漢字」のミッション）。
  書けなかった字は数えない。

## 採点結果の返し方（結果画面での説明）

`gradeStrokes` は合計点のほかに、児童へ理由を示すための材料も返す。

| フィールド | 内容 |
| --- | --- |
| `breakdown` | 項目ごとの `{ key, points, max, evaluated }`。按分後の満点込みなので、画面側で配点を再計算しなくてよい |
| `strokeFeedback` | 画ごとの `{ matched, inOrder, shape, reversed, ending }` |
| `details` | 児童向けの講評文 |
| `strokeCountMatch` / `orderMatch` / `crossMatch` | 合否を分ける3条件 |

`evaluated: false` の項目（例：手本に筆画種が無く終筆を採点できない）は `max` も0にしてあり、
「0点を取った」のか「採点対象外だった」のかを画面で区別できる。
画数が違うときは採点そのものを行わないので `breakdown` は空配列になる。

マイドリルのテスト結果画面（`DrillTestView`）は、この内訳と `strokeFeedback` を使って
「どの画で」「どの観点で」点を落としたかを、書いた線の色分けと番号で示している。

## KanjiVG キャッシュの形式

`kvg:type` を持たせるため、IndexedDB のキャッシュは `string[]`（d属性のみ）から
`{d, type}[]` に変わった。旧形式も読めるようにしてあり、オンラインなら取り直し、
取り直せなければ旧データのまま使って終筆の採点だけを見送る。

`test/analyzer.test.js` / `test/stroke-grader.test.js` / `test/careless.test.js`（`npm test`）。
交差判定が書く速さに左右されないこと、書き順の誤りが合格しないこと、
